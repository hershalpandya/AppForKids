# Practical quality checks for AppForKids

Research for AGP 8.13.2, Gradle 8.13 and Java 17; 2026-11-28. Recommendations are engineering judgment, not claims that upstream mandates every setting. Existing CI already runs release lint, release unit tests, builds and offline emulator smoke tests; preserve those behavioral checks.

## Recommended gates

- **Android lint:** run both `./gradlew :app:lintDebug :app:lintRelease` so variant-specific code and resources are covered. Set `android { lint { abortOnError true; warningsAsErrors true } }` after resolving findings; keep default checks rather than replacing them with `checkOnly`. If an immediate cleanup is impractical, a reviewed, checked-in baseline can gate new findings, with a plan to reduce it. Release lint may require the existing generated release catalogue, so use the existing CI setup. [Android lint](https://developer.android.com/studio/write/lint.html), [Lint DSL](https://developer.android.com/reference/tools/gradle-api/8.13/com/android/build/api/dsl/Lint).
- **Java:** explicitly set `compileOptions { sourceCompatibility JavaVersion.VERSION_17; targetCompatibility JavaVersion.VERSION_17 }`; retain the Java 17 runner. The source setting controls language features, while Android API availability still depends on compile SDK and desugaring. Consider `tasks.withType(JavaCompile).configureEach { options.compilerArgs += ['-Xlint:all', '-Werror'] }` after inspecting generated/third-party warnings and fixing actionable issues: it is stricter, but toolchain upgrades can produce new warnings. [Android Java versions](https://developer.android.com/build/jdks), [JDK 17 javac](https://docs.oracle.com/en/java/javase/17/docs/specs/man/javac.html).
- **Python:** pin `ruff==0.16.8` in a dedicated development requirements file and pin the CI Python minor version to the project-supported minimum once established. Use explicit `target-version` matching that minimum and explicit `lint.select = ["E4", "E7", "E9", "F", "I", "B"]` in `pyproject.toml`; run `python -m ruff check scripts tests`, `python -m ruff format --check scripts tests`, and `python -m unittest discover -s tests`. Apply and review Ruff formatting and fixes once before enforcing. Ruff 0.16 expanded defaults, so explicit rules avoid silently changing scope upon upgrade. Formatting is a project choice; PEP 8 specifically values consistency and permits pragmatic exceptions. [Ruff configuration](https://docs.astral.sh/ruff/configuration/), [Ruff releases](https://github.com/astral-sh/ruff/releases/tag/0.16.8), [PEP 8](https://peps.python.org/pep-0008/), [unittest discovery](https://docs.python.org/3/library/unittest.html#test-discovery).
- **CI:** keep `permissions: contents: read`, timeout, failing artifact upload and separate emulator coverage. Pin each action, including first-party actions, to an independently verified full commit SHA with an update comment; avoid interpolating untrusted event data into shell code. Keep `pull_request` for PR execution and keep secrets and privileged `pull_request_target` away from untrusted checkout. [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use), [workflow permissions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions).
- **Gradle wrapper:** retain the pinned distribution and `distributionSha256Sum` already present; validate the wrapper JAR in CI using the Gradle wrapper-validation action pinned to a verified full SHA. Distribution verification and wrapper JAR validation address different artifacts. [Gradle wrapper](https://docs.gradle.org/8.13/userguide/gradle_wrapper.html), [Gradle GitHub Actions](https://docs.gradle.org/current/userguide/github-actions.html).

## Tradeoffs, not automatic gates

- **Typing:** the scripts are mostly unannotated and consume dynamic JSON. Mypy normally skips unannotated function bodies; `check_untyped_defs` checks bodies but arguments remain `Any`, so a green run is not comprehensive type safety. Adopt gradually, starting with stable release interfaces and explicit JSON validation, then enforce `disallow_untyped_defs` per completed module. Pin a chosen mypy version when actually adopting it; do not add a nominal `--strict` gate without making annotations meaningful. [Mypy existing code](https://mypy.readthedocs.io/en/stable/existing_code.html), [dynamic typing](https://mypy.readthedocs.io/en/stable/dynamic_typing.html).
- **Gradle warnings:** run `./gradlew --warning-mode all ...` to inspect deprecations; use `--warning-mode fail` as a gate only once AGP and project warnings are understood, since dependency/plugin warnings can block upgrades. `validatePlugins` validates authored Gradle plugin task classes and is not a general Android application validation task. Configuration-cache checks are optional and require compatibility verification; they do not substitute for lint and tests. [Gradle 8.13 CLI](https://docs.gradle.org/8.13/userguide/command_line_interface.html), [plugin validation](https://docs.gradle.org/current/userguide/validation_problems.html).
- **Dependency verification:** checksum/signature verification is useful supply-chain hardening but needs review of trusted artifacts and ongoing updates; bootstrapping checksums from the currently resolved graph alone does not establish authenticity. [Gradle dependency verification](https://docs.gradle.org/8.13/userguide/dependency_verification.html).

## Applied in this repository

- CI and the pre-commit hook run Ruff and strict mypy for the Python scripts and tests, with Python 3.10 as the minimum supported interpreter. Dynamic JSON values are validated at the release-tool boundary.
- The production Python release tool has a 70% line-coverage threshold. Its CLI tests run in two reproducible shuffled orders, and coverage follows subprocesses. Test-driver scripts are not included in that production denominator. [Coverage.py subprocess measurement](https://coverage.readthedocs.io/en/latest/subprocess.html) · [Coverage thresholds](https://coverage.readthedocs.io/en/latest/commands/cmd_reporting.html)
- Java source formatting uses pinned [Google Java Format 1.28.0](https://github.com/google/google-java-format/tree/v1.28.0), with a verified release-asset checksum. Android lint checks debug and release, treats new warnings as errors, and tracks existing findings in `app/lint-baseline.xml`; version-update notices remain informational.
- Coverage and shuffled-order tests use real code and installed-app interactions; do not add mocks or fakes.
- Android line coverage is measured on the installed app, not with JVM unit tests: most app code is the activity UI, and `SharedPreferences`, assets and views would otherwise need test doubles. The `coverage` build type (`initWith release`, so release assets and `BuildConfig.DEBUG == false`) is the test build type, which is the build type the Android Gradle plugin instruments with JaCoCo offline instrumentation. [AGP test coverage](https://developer.android.com/reference/tools/gradle-api/8.13/com/android/build/api/dsl/BuildType) · [JaCoCo offline instrumentation](https://www.jacoco.org/jacoco/trunk/doc/offline.html)
- JaCoCo keeps execution data in memory and Android stops processes without a JVM shutdown, so `jacoco-agent.properties` disables the automatic dump. A coverage-only `CoverageDumpReceiver` writes the data on request, and `scripts/app_coverage.py` saves it before every force-stop or data clear in the test scripts. The denominator is every class in `be.hershalpandya.appforkids` except generated `BuildConfig`/`R` classes and the receiver itself; preview-only (`BuildConfig.DEBUG`) branches count as uncovered.
- Installed-app suites (review regressions and the starter smoke test) each start from cleared data and run in an order shuffled by `scripts/installed_suites.py`. CI seeds it with the run number and logs the order, so a failure caused by the order can be replayed. The release job keeps its fixed order because its in-place update check deliberately verifies the progress saved by the starter smoke test.
